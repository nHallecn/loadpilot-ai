# Priority 3 — Browser Validation and Recording Handoff

## Scope and truthfulness

This milestone adds automated **Chromium end-to-end browser tests** for the running Next.js dashboard and the real Fastify bounded experiment engine. It does **not** access the owner's private GitHub Codespace, Meta credential, or recording application. Only AI responses are **explicitly injected fixtures** in CI; all test runs and latency measurements are generated by real Fastify.inject executions.

CI screenshots and fixture-generated AI explanations are **test artifacts, not a live Muse Spark demonstration**. The final hackathon video must use real Meta Model API calls and real application measurements in the owner's private Codespace.

## Browser test coverage

- Open the actual dashboard in headless Chromium; wrong dashboard access token is rejected and correct one works.
- Request an AI plan through the Next.js gateway (mocked Meta planner response), verify the resulting plan is displayed.
- Run two actual five-second bounded synthetic experiments, compare measured p95/throughput and display diagnosis (AI text fixture, evidence independent).
- Execute two additional matched pairs with the real runner, render descriptive verdict, download a JSON report and recompute its SHA-256 checksum.
- Select a real low-load plan, run all three controlled variants with the actual runner, and show both one-factor contrasts.
- Ask the injected hypothesis agent for a proposal; verify that **no run is launched before the explicit user approval click**.
- Approve two real measured retests, then request fixture-model reassessment; verify that verified citations and the new evidence verdict appear.
- Assert there are no uncaught browser runtime errors.

Both backend and frontend listen on **127.0.0.1 only** in the test. Fixed test-only tokens are supplied directly to isolated CI processes; no real secret is read, and the fixture server refuses to start if `MODEL_API_KEY` is present.

## Running the automated browser test locally

From repository root, after ensuring ports 3000 and 4000 are free:

    pnpm install
    npm install --prefix tests/browser --no-package-lock
    node tests/browser/node_modules/playwright/cli.js install chromium
    node tests/browser/e2e.mjs

The script launches the fixture API and Next.js itself, drives a headless browser, verifies controls, then terminates both child processes. Do **not** point the script at a Codespace containing real production/test secrets. It runs only against loopback localhost and overrides environment tokens with known test-only values.

After a CI run, open the `loadpilot-browser-ci` artifact in GitHub Actions: it contains `passed-dashboard.png` or `failed-dashboard.png` and test-only process logs. These artifacts are retained for seven days.

## Run real Muse Spark in your private Codespace

1. Review/merge the prerequisite AI hypothesis PR first, then this testing PR; pull the updated `main` into your Codespace.
2. Install dependencies and start Fastify on `127.0.0.1:4000` from `apps/api`:

       node --env-file=.env --import tsx src/server.ts

3. In a second terminal, start Next.js from `apps/web` (with your existing private `apps/web/.env.local`):

       pnpm dev

4. Open the private port 3000 preview; unlock it with your `DASHBOARD_ACCESS_TOKEN`.
5. Use **Use low-load baseline**, then **Isolate bottleneck factors**. Inspect the three actual measured runs and the two factor contrasts.
6. Click **Ask Muse to choose a hypothesis**. Verify it returns a valid, cite-backed proposal (first paid call). If rate-limited or invalid, do not fabricate a result.
7. Read the proposed plan and click **Approve & run these 2 local tests**. These two real runs are bounded; confirm their p95 measurements appear.
8. Click **Ask Muse to reassess** (second paid call). Confirm its verdict and four numeric evidence references. A model response that contradicts the evidence should fail, not appear as validated.
9. Run a standard two-variant comparison, an ordinary AI diagnosis, and optional repeatability export. Inspect test report checksums if shown.
10. Record authentic video footage of the tested interface; use `docs/DEMO_SCRIPT.md` and `docs/SUBMISSION.md` as source material, keeping the final video **within three minutes**.

## Expected limitations

- No access to the user's private Codespaces browser/ports/credentials from this GitHub connector; actual Codespaces verification and recording remain manual.
- The browser CI fixture does **not** verify real Meta API availability, credits, structured-output compliance in the live account, or billing.
- Screenshot assertions are functional, not pixel-diff visual quality evaluations.
- The synthetic environment excludes Internet load testing, randomized controlled experiments and claims of root-cause proof.
- In-memory history and model session storage expire after restart; perform the demo in one running backend session.

## Release criteria before submitting

1. GitHub CI passes unit tests, typechecks, production build, and Chromium browser E2E.
2. Owner manually verifies complete dashboard flow with **real Meta Muse Spark** in their private Codespace.
3. Real measurements and recorded Muse outputs are visible in the three-minute video. No mocked or prefilled results presented as real Meta output.
4. Video link can be opened by a judge and official submission receipt has been captured before the deadline.
